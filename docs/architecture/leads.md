# Обработка заявок

Статус: проект. Окончательные решения не приняты, см. «Открытые вопросы».

## Требования

- Форма на сайте отправляет заявку сразу в три канала: **Telegram**, **Max** и **личную почту**.
- Потеря заявки недопустима: сбой одного канала не должен ронять остальные или терять данные.
- Прод: статический сайт на **Beget** + серверный `/api/lead`.
- Стейджинг: **Netlify** (только статика). Секреты каналов и `PUBLIC_LEAD_ENDPOINT` там не задаём — форма не бьёт в прод. См. [deploy.md](./deploy.md).
- Параллельно подключается **Callibri** для сообщений из мессенджеров и соцсетей.

## Что известно о каналах

Сведения собраны 2 ноября 2026 года из документации и публикаций. Всё, что касается доступности с хостинга, нужно проверить на реальном аккаунте.

| Канал | Как отправляем | Ограничения и риски |
|---|---|---|
| Почта | SMTP с авторизацией через ящик домена (предпочтительно) или `mail()` | Не проверено, что разрешено на тарифе Beget. SMTP даёт лучшую доставляемость (SPF, DKIM) |
| Max | `POST https://platform-api2.max.ru/messages?chat_id=<id>`, токен бота в заголовке `Authorization`, тело `{"text": "..."}` | Текст до 4000 символов, не больше 2 сообщений в секунду в один чат. Документация требует доверять сертификату Минцифры. Токен в query-параметрах не принимается. Получение `chat_id`: раздел «Получение chat_id» в документации Max |
| Telegram | Bot API, метод `sendMessage` | С марта 2026 появились сообщения, что `api.telegram.org` недоступен с российских серверов, в том числе с виртуального хостинга. Сегодняшнее состояние на Beget неизвестно |

## Поток данных

1. Форма (React-остров `LeadForm`) проверяет поля и отправляет `POST` с JSON на `/api/lead`.
2. Серверный эндпоинт проверяет метод, размер запроса, honeypot, время заполнения, частоту запросов с IP, поля и согласие.
3. **Заявка сначала сохраняется** (файл вне публичной папки или MySQL), и только потом уходит в каналы.
4. Каналы получают заявку независимо друг от друга, с таймаутом 5–10 секунд на канал. Результат по каждому каналу пишется в запись заявки.
5. Пользователю возвращается успех, если заявка сохранена, даже если часть каналов не ответила.
6. Cron раз в несколько минут повторяет отправку в упавшие каналы. После заданного числа неудач уведомление уходит в тот канал, который работает.

## Контракт запроса

| Поле | Тип | Обязательное | Правила |
|---|---|---|---|
| `name` | строка | да | 2–100 символов |
| `phone` | строка | да | нормализуется, 10–15 цифр |
| `email` | строка | нет | корректный адрес |
| `message` | строка | нет | до 2000 символов |
| `service` | `landscape`, `renovation`, `other` | нет | направление, с которого пришла заявка |
| `consent` | boolean | да | только `true` |
| `page` | строка | автоматически | путь страницы, откуда отправлена форма |
| `utm` | объект | нет | `utm_source`, `utm_medium`, `utm_campaign` и др. |
| `website` | строка | нет | honeypot: должно быть пустым |
| `startedAt` | число | да | время открытия формы; слишком быстрая отправка считается спамом |

Ответы: `200 {"ok": true}`, `400 {"ok": false, "errors": {...}}`, `429` при превышении частоты, `500` только если заявку не удалось сохранить.

## Сообщение в каналах

Один шаблон для всех каналов, обычный текст без разметки, чтобы данные пользователя не ломали форматирование:

```
Новая заявка с сайта
Имя: ...
Телефон: ...
Направление: ...
Сообщение: ...
Страница: ...
Время: ...
```

## Безопасность

- Секреты хранятся в конфигурации вне публичной папки хостинга и не попадают в репозиторий. В репозитории только `.env.example` с именами переменных.
- Секреты не должны попадать в клиентский код Astro: переменные с префиксом `PUBLIC_` видны всем.
- Эндпоинт принимает только `POST` с JSON и ограничивает размер тела.
- Защита от спама: honeypot, проверка времени заполнения, лимит по IP. Капчу (например, Yandex SmartCaptcha) добавим, если этого не хватит.
- В логах не хранить лишние персональные данные. Нужны срок хранения заявок и их очистка.

## Telegram: варианты из-за блокировок

- **A. Напрямую с хостинга.** Сначала проверяем доступность (см. ниже). Если работает, это самый простой вариант.
- **B. Через ретранслятор за рубежом** (небольшая serverless-функция, пересылающая запрос в Telegram). Работает, но добавляет сторонний узел, который тоже могут ограничить, и передачу данных через зарубежную площадку.
- **C. Telegram как необязательный канал.** Заявки надёжно идут в Max и на почту, а Telegram получает их, когда доступен.

Архитектура выше допускает любой исход: каналы независимы и повторяются через cron. Вариант выбираем после проверки.

## Callibri

Я понимаю запрос «calibri» как сервис [Callibri](https://callibri.ru). Если речь о другом, нужно уточнить.

- Что это: онлайн-чат и виджет, собирающий сообщения из мессенджеров и соцсетей в одном окне; есть форма сбора контактов.
- Каналы по странице продукта: WhatsApp, Telegram, VK. Max на этой странице для виджета не указан, это нужно уточнить в Callibri.
- Тариф: виджет доступен на тарифах L и XL CRM-чата; есть пробный период.
- Установка: сторонний скрипт, как у систем аналитики. Код берётся в кабинете Callibri.
- Интеграция в проекте: компонент `CallibriWidget.astro`, подключаемый в `BaseLayout.astro` и включаемый переменной окружения. Скрипт грузим отложенно, чтобы не ронять Lighthouse.
- Согласие: нужен баннер согласия на cookie и обработку данных, решение принимаем вместе с политикой конфиденциальности.
- Наша форма и Callibri независимы: форма идёт через собственный эндпоинт, чаты через Callibri. Сквозную аналитику и сопоставление обращений обсудим позже.

## Открытые вопросы и проверки на Beget

Проверки выполняются по SSH на хостинге, если он доступен на тарифе. Для Max возможна ошибка сертификата без сертификата Минцифры; важно, устанавливается ли соединение.

```
curl -sS -m 10 -o /dev/null -w "%{http_code}\n" https://api.telegram.org
curl -sS -m 10 -o /dev/null -w "%{http_code}\n" https://platform-api2.max.ru
```

1. Версия PHP и разрешены ли исходящие запросы (cURL) с хостинга.
2. Доступность `api.telegram.org` и `platform-api2.max.ru` (команды выше).
3. Отправка почты: SMTP или `mail()`, лимиты и доставляемость.
4. Доступен ли cron на тарифе.
5. Хранение заявок: файл или MySQL.
6. Подтвердить, что речь о Callibri, выбрать тариф и узнать, поддерживается ли Max.
7. Правовая сторона хранения и передачи персональных данных (152-ФЗ), в том числе при передаче через зарубежный ретранслятор. Это вопрос к юристу, я не могу дать заключение.

## План работ

1. Проверки на Beget.
2. Серверный эндпоинт и тест на одной почте.
3. Подключение Max, затем Telegram по результату проверки.
4. Остров `LeadForm` по макету из Figma.
5. Callibri.
6. Повторная отправка через cron и уведомления о сбоях.
