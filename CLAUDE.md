# monolit

Сайт компании: ландшафтный дизайн и ремонт квартир под ключ.
Главная цель сайта — заявки (форма и звонок). В течение первого года правки на сайте вносит разработчик, поэтому контент хранится в репозитории, без CMS.

## Стек

- Astro, статическая генерация (SSG), TypeScript в строгом режиме
- React — только для интерактивных островов (калькулятор, форма, галерея); остальное на `.astro` без клиентского JS
- Хостинг: Beget. Сайт статический: собирается в `dist/` и загружается на хостинг. SSR и серверные адаптеры без согласования не используем
- Форма заявок: небольшой серверный скрипт на стороне хостинга (вариант уточняется)
- Менеджер пакетов: npm
- Дизайн: Figma

Ещё не решено: подход к стилям, способ обработки формы (PHP-скрипт или Node), способ деплоя (вручную или через CI). Не выбирай за пользователя, предложи варианты и спроси.

## Команды

- `npm run dev` — сервер разработки
- `npm run build` — сборка в `dist/`
- `npm run preview` — просмотр собранного сайта
- `npm run check` — проверка типов (`astro check`)
- `npm run release` — релиз (см. «Git и версионирование»)

## Структура (целевая)

- `src/pages` — страницы и маршруты
- `src/layouts` — общие шаблоны
- `src/components` — компоненты (`PascalCase.astro`)
- `src/content` — типизированные коллекции: услуги, кейсы портфолио
- `src/styles/tokens.css` — дизайн-токены (цвета, шрифты, отступы)
- `public` — статические файлы
- `docs/design` — референсы, разборы и список компонентов

## Код

- TypeScript strict, без `any`
- Не добавляй зависимости без согласования
- Небольшие компоненты, одна ответственность
- Не выдумывай данные компании (цены, адреса, телефоны, отзывы): используй явные плейсхолдеры

## Дизайн

- Макеты в Figma — источник правды
- Цвета, шрифты и отступы только из токенов, без захардкоженных значений
- Адаптивность mobile-first

## SEO (обязательно для каждой страницы)

- `<html lang="ru">`, уникальные `title` и `description`
- Один `h1`, корректная иерархия заголовков, семантическая разметка
- `canonical`, Open Graph, понятные URL
- `alt` у всех содержательных изображений
- JSON-LD: LocalBusiness и Service там, где уместно
- `sitemap.xml` и `robots.txt`

## Производительность и доступность

- Изображения только через встроенную оптимизацию Astro, с заданными размерами и ленивой загрузкой
- JavaScript на клиенте — минимум
- Цель: 90+ в Lighthouse (mobile)
- Доступность по WCAG 2.1 AA: контраст, фокус с клавиатуры, подписи у полей форм

## Форма заявок

- Валидация на клиенте и на сервере, защита от спама (honeypot)
- Секреты только в переменных окружения, в репозиторий не попадают (`.env.example` с именами переменных)
- Согласие на обработку персональных данных и ссылка на политику конфиденциальности

## Git и версионирование

- Conventional Commits: `feat`, `fix`, `perf`, `refactor`, `docs`, `style`, `chore`, `test`, `build`, `ci`
- Формат: `тип(область): краткое описание`; ломающее изменение — `!` после типа или `BREAKING CHANGE:` в теле
- Тип пишется без скобок: `chore: ...`, а не `(chore): ...`. Иначе `commit-and-tag-version` не распознает коммит
- Ветки: `main` — стабильная, работа в `feature/...` и `fix/...`
- Версии и тэги ведёт `commit-and-tag-version`: `feat` → minor, `fix` → patch, ломающее изменение → major
- Не правь `CHANGELOG.md` и поле `version` в `package.json` вручную
- Релиз делается из `main` с чистым рабочим деревом:
  - первый релиз: `npm run release:first`
  - обычный релиз: `npm run release`
  - пробный запуск без изменений: `npm run release:dry`
  - запуск сайта: `npm run release -- --release-as 1.0.0`
  - после релиза: `git push --follow-tags origin main`
